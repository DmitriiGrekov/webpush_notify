## Возможности локальной разработки

### Автоматическое определение окружения
Проект автоматически определяет режим работы:
- **Локально**: Использует SQLite, DEBUG=True
- **Production**: Использует PostgreSQL, DEBUG=False, HTTPS

### Быстрый запуск
```bash
# Один скрипт делает всё:
./run_local.sh  # или run_local.bat на Windows
```

### Что делает скрипт:
1. ✅ Создаёт виртуальное окружение (если нет)
2. ✅ Устанавливает зависимости
3. ✅ Копирует .env.local.example в .env (если нет)
4. ✅ Применяет миграции
5. ✅ Собирает статические файлы
6. ✅ Проверяет наличие суперпользователя
7. ✅ Запускает сервер разработки

### Преимущества

1. **Не требует Docker** - работает на любой системе с Python
2. **Быстрый старт** - один скрипт для запуска
3. **SQLite** - не нужно устанавливать PostgreSQL
4. **Горячая перезагрузка** - Django автоматически перезагружается при изменениях
5. **Простая отладка** - прямой доступ к коду и логам

## Использование

### Первый запуск

```bash
# 1. Клонировать репозиторий
git clone <repo-url>
cd pushsite

# 2. Запустить скрипт
./run_local.sh  # macOS/Linux
run_local.bat   # Windows

# 3. Открыть браузер
# http://localhost:8000
```

### Ежедневная разработка

```bash
# Активировать окружение
source env/bin/activate  # macOS/Linux
env\Scripts\activate     # Windows

# Запустить сервер
python manage.py runserver

# Или использовать скрипт
./run_local.sh
```

### Генерация VAPID ключей

```bash
python generate_vapid_keys.py
# Скопировать вывод в .env файл
```

## Миграция с Docker на локальную разработку

Если вы работали с Docker и хотите перейти на локальную разработку:

```bash
# 1. Остановить Docker
docker-compose down

# 2. Экспортировать данные (опционально)
docker-compose exec web python manage.py dumpdata > backup.json

# 3. Запустить локально
./run_local.sh

# 4. Импортировать данные (опционально)
python manage.py loaddata backup.json
```
